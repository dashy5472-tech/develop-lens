# 생기부 돋보기

나이스에서 내려받은 파일을 올리면, 학생끼리 겹치는 구간에 **유사 인원**을 표시하고
대학 서류평가에서 실제로 읽힐 **생존 분량**을 계산합니다.

파일은 브라우저 안에서만 열립니다. 서버로 올라가지 않고 어디에도 저장되지 않습니다.

---

## 어디에 올릴까

이 도구는 **이미 웹 앱입니다.** `index.html` 한 파일이 전부고 서버가 없습니다.
남은 일은 그 파일을 어디에 두어 링크를 만드느냐뿐입니다.

**먼저 알아 둘 것 — 접근 제한은 이 도구에서 거의 의미가 없습니다.**
생기부 내용은 서버로 가지 않습니다. 링크를 아무나 열어도 볼 수 있는 것은
**빈 도구**뿐이고, 자료는 여는 사람 브라우저 안에만 있습니다.
그래서 "학교 계정만 접근" 을 위해 불편을 감수할 이유가 크지 않습니다.

| | 링크 | 내려받기 | 로그인 | 손이 가는 정도 |
|---|---|---|---|---|
| **A. 정적 호스팅** (권장) | 깔끔한 주소 | 그대로 됨 | 없음 | 처음 10분 |
| **B. Apps Script** | 긴 주소 | **막힐 수 있음** | 학교 계정 | 처음 10분 |
| **C. 파일로 전달** | 없음 | 그대로 됨 | 없음 | 0분 |

**A 를 권합니다.** Apps Script 는 페이지를 iframe 안에 넣어 주는데,
그 iframe 에는 `allow-downloads` 가 없어 **브라우저가 자동 내려받기를 막습니다.**
[수정본 내보내기] 를 눌러도 아무 일이 없는 것처럼 보일 수 있다는 뜻입니다.
(그 경우를 대비해 새 탭으로 여는 길을 넣어 두긴 했습니다. 아래 B 참고.)

### A. 정적 호스팅 — GitHub Pages

1. [github.com](https://github.com) 가입 → **New repository** (이름 아무거나, Public)
2. **Add file → Upload files** 로 `index.html` 을 올리고 Commit
3. **Settings → Pages → Source** 를 `main` / `root` 로 두고 Save
4. 1~2분 뒤 `https://<아이디>.github.io/<저장소>/` 로 열립니다

파일을 고칠 때마다 다시 올리면 모두에게 한 번에 반영됩니다.
가입이 부담스러우면 [Netlify Drop](https://app.netlify.com/drop) 에
폴더를 끌어다 놓기만 해도 주소가 나옵니다.

> 저장소를 Public 으로 두어도 **올라가는 것은 도구뿐**입니다.
> 학생 기록은 절대 올리지 마세요.

### B. Apps Script — 학교 계정으로 막아야 할 때

학교 도메인 계정만 열 수 있게 하고 싶을 때만 쓰세요.

1. [script.google.com](https://script.google.com) → **새 프로젝트**
2. `Code.gs` 내용을 붙여넣기 (기본 `myFunction` 은 지우고)
3. 좌측 **파일 +** → **HTML** → 이름을 `index` 로 하고 `index.html` 내용을 붙여넣기
4. 좌측 **프로젝트 설정** → "`appsscript.json` 매니페스트 파일 표시" 체크
   → 편집기로 돌아가 `appsscript.json` 을 이 저장소 내용으로 교체
5. 우측 상단 **배포 → 새 배포 → 웹 앱**
   - 실행 계정: **웹 앱에 액세스하는 사용자**
   - 액세스 권한: **(학교 도메인) 내 모든 사용자**
6. 나온 URL 을 공유

`appsscript.json` 의 `oauthScopes` 가 비어 있어 **권한 승인 화면이 뜨지 않습니다.**
학교 계정이 아니라 개인 Gmail 이면 5단계에서 `"access": "DOMAIN"` 을 `"ANYONE_ANONYMOUS"`
또는 `"MYSELF"` 로 바꿔야 합니다.

> **배포한 뒤 [수정본 내보내기] 를 꼭 한 번 눌러 보세요.**
> Apps Script 는 페이지를 iframe 안에 넣고, 그 iframe 에는 `allow-downloads` 가 없어
> 브라우저가 자동 내려받기를 막습니다. 그래서 이 도구는 iframe 안이라고 판단되면
> **파일을 새 탭으로 열어** 줍니다 — 거기서 저장하시면 됩니다.
> 조절판의 내보내기 설명에도 그 안내가 함께 뜹니다.
> 새 탭까지 막히면 팝업 차단을 풀거나, A 로 옮기거나, C 로 쓰세요.

### C. 파일 하나로 전달

`index.html` 을 더블클릭하면 브라우저에서 열립니다. 설치할 것도, 인터넷도 필요 없습니다.
다른 선생님께는 이 파일 하나만 보내시면 됩니다. 내려받기도 그대로 됩니다.

단 `.xlsx` 를 올릴 때만 해석 라이브러리를 한 번 내려받습니다.
학교 네트워크가 그 요청을 막으면 안내가 뜨고, 엑셀에서 `.csv` 로 저장해 올리시면 됩니다.
이건 A·B·C 모두 같습니다.

## 데이터가 나가지 않는다는 확인

말로만 하면 믿기 어려우니 직접 확인하실 수 있습니다.

- `index.html` 에서 `google.script.run`, `fetch(`, `XMLHttpRequest`, `sendBeacon` 을 검색해 보세요.
  `google.script.run` 이 **주석 한 줄에만** 나옵니다 — "서버 호출은 어디에도 없다"고 적어둔 그 줄입니다.
  나머지는 아예 나오지 않습니다.
- `Code.gs` 에서 `SpreadsheetApp`, `PropertiesService`, `CacheService`, `UrlFetchApp` 도 마찬가지로
  **없다고 적어둔 주석에만** 나옵니다. `Logger`, `DriveApp` 은 아예 없습니다.
- 브라우저 개발자도구 → 네트워크 탭을 켜고 파일을 올려 보세요. `.xlsx` 해석 라이브러리를
  내려받는 요청 외에는 아무 통신도 없습니다. 그 요청도 **내려받기만** 하고 보내지 않습니다.

파일 내용은 탭을 닫으면 사라집니다.

## 처음이시면 — 예시로 따라 해보기

첫 화면의 **[예시로 따라 해보기]** 를 누르면 지어낸 학생 서른여섯 명이 올라오고,
화면을 눌러 가며 익힐 수 있는 안내가 열다섯 걸음 이어집니다. 파일은 필요 없습니다.

안내가 떠 있는 동안에도 **화면은 그대로 눌립니다.** 덮개는 눈으로만 덮고
클릭은 통과시키기 때문에, 설명을 읽으면서 실제로 만져 볼 수 있습니다.
`←` `→` 로 넘기고 `Esc` 로 닫습니다. 위쪽 **[안내 다시 보기]** 로 언제든 다시 엽니다.

예시 학년에는 네 가지 상황이 **일부러** 심어져 있습니다.

| 심어 둔 것 | 누구 | 화면에서 |
|---|---|---|
| 토씨까지 같은 문장 | 1반 5번 · 11번 | 노란 칠 · `그대로 1명` · 같은 반 |
| 주제어만 바꾼 문형 | 2반 3 · 6 · 9 · 12번 | 하늘색 칠 · `문형 3명` · 같은 반 |
| 반을 넘어 퍼진 문형 | 1반 2번 · 2반 7번 · 3반 4번 | 하늘색 칠 · 같은 반 아님 |
| 모두가 쓴 수행평가명 | 서른여섯 명 전부 | 점선만 · 감점 없음 |

나머지 스물일곱 명은 고유하게 써서 생존 분량이 100% 입니다.
**색 있는 줄과 조용한 줄의 차이**가 바로 보이도록 만든 구성입니다.

> 예시의 반 구성(3반 × 12명)을 유지하세요. 2반 네 명짜리 문형 무리가 확인 대상으로
> 남는 것은 인원이 아니라 **한 반에 몰려 있기 때문**입니다. 반을 합치면 뜻을 잃습니다.
> `node _test_sample.js` 가 이 조건과 안내 문구의 사실 여부를 함께 지킵니다.

## 쓰는 법

1. 나이스에서 세특 등을 엑셀로 내려받습니다. (`.xlsx`, `.xls`, `.csv` 모두 됩니다.
   나이스가 `.xls` 확장자로 HTML 표를 주는 경우도 자동으로 처리합니다.)
2. 파일을 끌어다 놓습니다. **여러 개를 한꺼번에** 놓으셔도 됩니다.
3. **반·번호·내용 열**이 맞는지 확인합니다.
4. 분석 시작.

**학년 전체(200명 안팎)를 한 번에 넣으셔도 됩니다.** 계산은 200명 기준 130ms,
400명도 310ms 안에 끝납니다.

### 여러 반 파일을 한꺼번에

나이스는 **과목·반 단위로만** 파일을 뽑아 줍니다. 수학 네 반을 가르치면 파일도 네 개입니다.
그런데 유사도는 **비교 대상이 전부 모여 있어야** 의미가 있습니다. 한 반 안에서만 보면
"우리 반은 깨끗하다"가 나오지만, 네 반을 합치면 같은 문형이 반을 넘나들며 반복되는 게 보입니다.

그래서 파일 합치는 일은 사람이 하지 않습니다. 네 개를 한꺼번에 끌어다 놓으면 됩니다.

- 목록에서 파일별 인원이 보이고, **[빼기]** 로 하나씩 뺄 수 있습니다
- **[파일 더하기]** 로 나중에 계속 더할 수 있습니다
- 같은 파일을 두 번 올리면 **똑같은 행은 한 번만** 들어갑니다
- 파일마다 **열 순서가 달라도** 머리글 이름으로 맞춥니다
- 머리글 이름이 아예 달라도 (`세부능력 및 특기사항` / `내용`) **같은 칸으로 모읍니다**
- 머리글이 첫 줄에 없어도 (위에 제목 줄, 빈 줄이 있어도) **찾아냅니다**
- 어떤 파일에서 세특을 **한 건도 못 찾으면** 빨갛게 `세특 없음` 으로 알립니다 —
  양식이 다른 파일이 조용히 빠진 채 결과가 나오는 일이 없게 하려는 것입니다

같은 학생이 두 과목 파일에 다 있으면 이름표를 `3반 1번 · 대수` 처럼 과목으로 갈라 줍니다.
겹치지 않으면 `3반 1번` 그대로 둡니다.

### 화면 구성

분석 전에는 **업로드 화면**이 전체 폭을 쓰고, 분석 후에는 **3분할 작업 화면**으로 바뀝니다.

```
┌──────────────────────────────────────────────────────┐
│ 생기부돋보기  파일명 · 200명 [바꾸기]      ● 로컬 처리 │
├─────────┬────────┬───────────────────────────────────┤
│ 조절판   │ 명단    │ [기록] [반복 표현] [표]           │
│         │        │                                   │
│ 확인대상 │ 정렬·   │ 선택한 학생의 기록                 │
│ 6/200명 │ 반필터· │ 겹치는 구간에 색과 유사 인원       │
│ 평균 97%│ 검색    │ 겹치는 학생 목록                   │
│         │        │                                   │
│ 슬라이더 │ 생존순  │                                   │
│ 즉시반영 │ 목록    │                                   │
└─────────┴────────┴───────────────────────────────────┘
```

명단에서 학생을 클릭하면 **오른쪽만 바뀝니다.** 탭을 오갈 필요가 없어
200명을 위에서부터 훑어 내려가기 좋습니다.

화면이 좁으면 조절판과 명단이 서랍으로 접히고, 상단 버튼으로 열 수 있습니다.

### 보이는 순서를 정해 둔 규칙

고칠 때 무너뜨리기 쉬운 부분이라 적어 둡니다.

**색은 봐야 할 것에만 씁니다.** 명단 200줄에서 생존 분량이 85% 이상인 줄은
회색 막대와 옅은 숫자로 조용히 둡니다. 85% 아래면 주황, 60% 아래면 붉은색이 됩니다.
모든 줄이 색 막대였을 때는 문제 있는 줄이 그 속에 묻혔습니다.
기록 화면의 생존 분량도 같은 규칙을 따릅니다 — 같은 뜻이 자리마다 다른 색으로 보이면 안 됩니다.

**한 줄에 알약은 하나뿐입니다.** `같은 반 2` 만 그 자격이 있습니다 —
조치가 정해진 유일한 신호이기 때문입니다. `확인 3곳` 은 그냥 옅은 글씨입니다.

**같은 반 겹침은 생존 분량과 별개 채널입니다.** 생존 95% 라도 같은 반과 겹치면
봐야 하므로, 숫자 색을 물들이지 않고 알약으로 따로 세웁니다.

**글자 크기는 여섯 단만 씁니다.** `--t-xs` 부터 `--t-hero` 까지 토큰으로 정해 두었고,
`--t-xl` 은 **지금 보는 학생 이름** 전용입니다. 손으로 박은 크기가 하나라도 남으면
`node _test_html.js` 가 잡아냅니다.

**반복 표현 세 묶음은 심각도가 다릅니다.** 글자 그대로 반복(빨강 띠) →
문형 반복(주황 띠) → 공통 활동으로 제외(바탕 없음) 순입니다.

**설명은 접어 둡니다.** 처음 한두 번만 읽히는 글이 화면을 차지하지 않도록,
한 줄 요점만 남기고 나머지는 `?` 도움말로 접었습니다.

### 색 — 맑은 아침

버터 크림 바탕에 **하늘빛** 강조, **노랑**과 **아쿠아**로 겹침 표시, **주황**으로 주의입니다.
겹침 표시 두 색 `#FFF4B8` · `#BEFAF4` 는 쓰는 사람이 고른 색을 그대로 씁니다.

**밝은 화면 한 벌로만 갑니다.** 어두운 화면 판은 두지 않습니다 — 안 고쳐진 채 남으면
값이 어긋나기 때문입니다. `color-scheme: light` 를 박아 두어 운영체제가 어두워도
스크롤바·드롭다운만 검게 나오는 일이 없습니다.

**파스텔이되 글자는 아닙니다.** 흰 바탕에서 4.5:1 을 넘으려면 색이 어두워야 하는데
파스텔은 정의상 밝습니다. 그래서 파스텔은 **칠과 바탕**에만 쓰고,
글자와 선은 **같은 색조를 지킨 깊은 판**을 씁니다.

단추가 그 예입니다. `--accent-lite` `#93BEF0` 은 종이 위에서 1.9:1 이라 글자로는 못 씁니다.
대신 칠로 두면 그 위 본문색 글자가 8.5:1 로 읽히므로, 단추 바탕에 두고
글자·선에는 같은 색조 212° 의 `--accent` `#186ED2` (4.95:1) 를 씁니다.

**옅은 칠 세 개는 올라가는 글자가 달라 따로 둡니다.**
`--accent-soft` 는 선택된 줄(주의·경고 숫자까지 올라감 → 밝아야 함),
`--accent-fill` 은 요약 블록(강조와 보조만 올라감 → 진해도 됨),
`--accent-lite` 는 단추 칠입니다. 하나로 묶으면 가장 빡빡한 쪽에 맞춰야 해서
요약 블록이 종이에 묻힙니다.

**주의와 경고는 색상이 아니라 밝기로 갈라 두었습니다.** 색각 이상에서 주황과 빨강은
거의 같은 색이 됩니다 — 눈으로 고른 값은 ΔE 1.8 까지 떨어졌습니다. 밝기 차이는 살아남습니다.

**겹침 표시는 색을 못 가려도 읽힙니다.** 칩 글자가 `그대로 2명` / `문형 4명` 으로 서로 달라서,
노랑과 아쿠아를 구분하지 못해도 어느 겹침인지 알 수 있습니다.

색을 바꾸면 두 검사를 모두 통과해야 합니다.

- `node _test_color.js` — 30쌍. 작은 글자 4.5:1, 그래픽 3:1
- `node _test_cvd.js` — 나란히 놓이는 짝이 protan·deutan·tritan 에서 OKLab ΔE 8 이상.
  숫자나 글자가 같은 뜻을 한 번 더 말해 주는 자리는 6 까지 허용합니다.

### 초깃값은 재어서 정했습니다

감으로 고르지 않았습니다. 예시 학년은 **정답을 아는 자료**입니다 —
아홉 명은 일부러 심었고 스물일곱 명은 고유하게 썼습니다.
그래서 설정을 바꿔 가며 **놓친 것**과 **헛짚은 것**을 직접 셀 수 있습니다.
`node _tune.js` 로 다시 재 보실 수 있습니다.

**최소 구간 길이 20자** — 헛짚음이 0이 되는 **가장 낮은 값**입니다.

```
 8자   놓침 0 · 헛짚음 11      ← 잡음뿐
12자   놓침 0 · 헛짚음  2
16자   놓침 0 · 헛짚음  2
20자   놓침 0 · 헛짚음  0      ← 여기
```

실제 기록 25명에서도 같은 무릎이 나옵니다 (24명 → 13 → 8 → **6** → 3 → 2 → 0).
28자를 넘기면 수행평가명 자체를 못 잡기 시작합니다.

**공통 활동 기준 10%** — 낮게 둘 수 있는 것은 **인원만 보지 않기 때문**입니다.

처음에는 인원만 봤습니다. 그때는 낮추는 게 위험했습니다.

```
돌려쓴 무리      12%     20%     25%     33%     40%
5명 (반의 절반)    ✗       ✓       ✓       ✓       ✓
7명               ✗       ✗       ✗       ✓       ✓
9명 (반 전체)      ✗       ✗       ✗       ✗       ✓
```

**한 반 전체가 돌려 쓰면 그 반이 다 같이 쓴 수행평가명과 인원이 똑같습니다.**
숫자로는 절대 못 가릅니다. 활동명을 직접 적어도 해결되지 않습니다 —
적기와 기준은 **둘 다 빼는 방향으로만** 작동해서, 기준이 이미 빼 버린 것을
적기로 되살릴 수 없기 때문입니다.

```
10% · 안 적음        2반 아홉 명 돌려쓰기 → 0/9명 잡음   생존 100%
10% · 활동명 다 적음  2반 아홉 명 돌려쓰기 → 0/9명 잡음   생존 100%
```

**그래서 숫자 대신 퍼진 모양을 봅니다.**

> 한 반에 몰린 구간은 인원이 아무리 많아도 활동명으로 빼지 않습니다.
> 진짜 공통 활동은 여러 반에 걸쳐 있습니다.

이 규칙을 넣으니 위험 구간이 사라졌습니다.

```
기준    인원선   2반 아홉 명 돌려쓰기   학년 공통 도입부
 5%       3명           9/9명 잡음         빠짐 ✓
10%       3명           9/9명 잡음         빠짐 ✓
40%      11명           9/9명 잡음         빠짐 ✓
```

기준을 아무리 낮춰도 한 반 돌려쓰기는 살아남고, 여러 반에 걸친 도입부는 잘 빠집니다.
그래서 **낮게 둡니다** — 손으로 적을 일이 줄고, 잃는 것이 없습니다.

**남는 두 가지.**

- 반이 **하나뿐**이면 퍼진 모양을 볼 수 없어 인원만으로 판단합니다.
  그때는 낮추면 위험하고, 조절판이 붉게 알립니다.
- 여러 반에 **걸친** 문형은 낮은 기준에서 빠질 수 있습니다. 이건 한 교사의
  돌려쓰기가 아니라 전국적 상투어에 가까워, 원래 덜 급한 신호입니다.

`node _test_defaults.js` 가 이 근거를 지킵니다. 특히
"기준을 아무리 낮춰도 한 반 돌려쓰기는 안 빠진다" 를 확인합니다.

### 조절판은 위에서 아래로

**아는 것을 먼저 알려 주고, 모르는 것을 그다음에 어림하는** 순서입니다.
이름만으로는 무엇을 정하는 건지 알 수 없어서, 각 칸 아래에
**지금 값이 실제로 무슨 뜻인지**를 보여 줍니다.

```
① 활동명 직접 적기   ← 아는 것. 가장 정확
② 최소 구간 길이     ← 얼마나 짧은 겹침까지 볼지
③ 공통 활동 기준     ← ①에서 못 적은 것을 인원으로 어림. 추측
```

### ① 활동명 직접 적기

무엇이 수행평가명인지는 가르친 사람이 이미 압니다. 한 줄에 하나씩 적으면,
**몇 명이 썼든** 감점에서 뺍니다.

```
2학기 융합탐구 프로젝트
삼각측량 활동
「침묵의 봄」
```

두 명만 같은 수행평가를 했다면 자동 기준(최소 3명)에 걸리지 않아 감점 대상으로 남습니다.
슬라이더를 내려도 이 경우는 잡히지 않습니다. 직접 적는 칸이 필요한 이유입니다.

**적은 자리만 도려냅니다.** 활동명 뒤에 진짜 복붙이 붙어 있으면,
활동명은 빼고 복붙은 확인 대상으로 남깁니다.

```
적기 전  [2학기 융합탐구 프로젝트 수행평가에서 자료를 수집하고 … 발표하였음.]  ← 통째로 감점

적은 뒤  (2학기 융합탐구 프로젝트 수행평가에서) [자료를 수집하고 … 발표하였음.]
          └ 공통 활동으로 뺌               └ 여전히 감점
```

통째로 빼면 붙어 있던 복붙까지 사라지고, 통째로 두면 적은 것이 소용없어집니다.

**반복 표현 탭에서 눌러 담을 수도 있습니다.** `그대로 반복` 목록에서 수행평가명이 보이면
옆의 **[활동명]** 을 누르세요. 조절판에 담기고 곧바로 다시 계산됩니다.
직접 적은 것은 공통 활동 목록에 `직접 지정` 으로 표시됩니다.

네 글자 이상만 받습니다. 두세 글자를 받으면 엉뚱한 곳까지 활동명으로 빠집니다.

### ② 최소 구간 길이

두 학생이 이보다 짧게 겹친 곳은 아예 세지 않습니다.
「삼각비」 같은 전문용어나 「하였음」 같은 말끝은 누구나 쓰는 말이라,
짧은 겹침까지 세면 온 학년이 확인 대상이 됩니다.
반대로 너무 올리면 짧게 베낀 곳을 놓칩니다.

"20자" 라는 숫자만으로는 그게 얼마인지 모르므로, **그 길이만큼 실제로 칠해** 보여 줍니다.

```
이만큼 겹쳐야 표시합니다
[자료를 수집하고 분석하는 과정을 거쳤]        ← 20자
```

### ③ 공통 활동 기준

활동명을 하나하나 다 적을 수는 없습니다. **①에 적지 않은 것** 중에서
이 인원 이상이 함께 쓴 구간을 활동명으로 어림합니다 — 점선으로만 표시하고 생존 분량도 깎지 않습니다.
**단, 한 반에 몰린 구간은 인원이 많아도 빼지 않습니다.**

**"여럿이 쓰면 활동명일 것" 이라는 추측**이라 ①만큼 정확하지 않습니다.
그래서 순서가 ① 다음입니다. 뺀 구간은 `반복 표현` 탭 맨 아래에서 확인하시고,
활동명이 아닌 것이 섞여 있으면 기준을 내리세요.

비율로 정하는 것은 학년 인원이 달라도 같은 뜻이 되게 하려는 것입니다.
다만 판단에 실제로 쓰이는 건 **인원**이라, 그 숫자를 계산해 보여 줍니다.

```
전체 36명 중 15명 이상이 함께 쓴 표현은
감점에서 뺍니다
```

이 인원은 `commonNeed()` 한 곳에서만 정합니다. 화면이 말하는 숫자와
실제 계산이 갈라지면 화면이 거짓말을 하게 되므로, 두 곳이 같은 함수를 씁니다.
`node _test_sample.js` 가 이 일치를 확인합니다.

### 같은 반 겹침 — 학년 단위로 돌릴 때의 핵심 신호

겹친 상대가 **같은 반인지** 표시합니다. 명단에는 `같은 반 2` 알약으로,
기록 화면에서는 겹친 구간 옆에 `그대로 3명 · 같은 반 2` 로 나옵니다.

전국적 상투어라면 여러 반에 골고루 퍼지지만, **한 반에 몰려 있으면
그 반을 맡은 교사가 돌려썼을 가능성**이 높습니다. 훨씬 눈여겨볼 신호라
붉게 표시하고 요약에도 따로 셉니다. 학년 전체를 한 번에 넣으셨을 때만 의미가 있습니다.

### 나이스 [세특 업로드 양식] 을 그대로 씁니다

나이스에서 내려받는 양식의 열 구성입니다. 채워서 그대로 올리시면 됩니다.

```
학년도 · 학기 · 학년 · 학생개인번호 · 과목 · 과목코드 ·
반/번호 · 성명 · 학적변동구분 · 세부능력 및 특기사항 · 영재·발명교육 기록사항
```

이 중 실제로 쓰는 건 셋입니다.

| 역할 | 머리글 | 비고 |
|---|---|---|
| 내용 | `세부능력 및 특기사항` | 세특, 특기사항, 내용 등도 인식 |
| 반·번호 | `반/번호` | `3/1` 형태를 자동으로 나눠 `3반 1번` 으로 표시 |
| 성명 | `성명` | **기본은 표시하지 않음** (아래 참고) |

**열은 위치가 아니라 머리글 이름으로 찾으므로 순서가 달라도 동작합니다.**
머리글이 첫 줄이 아니어도 (위에 제목 줄이나 빈 줄이 있어도) 앞쪽 열두 줄 안에서 찾아냅니다.
이름을 못 알아보면 글자 길이와 숫자 비율로 추정하고 "추정했습니다"라고 알립니다.
그때는 드롭다운으로 직접 지정하시면 됩니다.

### 이름은 기본으로 가립니다

결과에는 `3반 1번` 형태로만 나옵니다. 겹침을 재는 데 이름이 필요 없기 때문입니다.

조절판 **맨 위의 이름 표시**를 켜면 `3반 1번 홍길동` 으로 나옵니다. 명단·기록·표·관계망에
한꺼번에 적용되고, 켜고 끄는 즉시 바뀝니다.

**조절판 맨 위에 둔 이유** — 가장 자주 건드리는 항목이고, 화면을 공유하기 직전에
생각 없이 바로 손이 가야 합니다. 아래 ①②③ 은 한 번 맞추면 거의 안 건드립니다.
작업 중에 켜고 끌 수 있어야 하는 것도 이유입니다. 업로드 화면에만 있으면
이름을 보려고 **[바꾸기]** 로 되돌아가야 하고, 그러면 고친 기록이 날아갑니다.

성명 열이 없는 자료면 이 항목이 눌리지 않고, 왜 그런지 그 자리에 적힙니다.

처리가 전부 로컬이라 이름을 켜도 밖으로 나가지는 않습니다.
다만 **화면을 캡처해 공유하실 일이 있으면 꺼두세요.**

## 고칠 때 반드시 돌릴 것

```
node _test_boot.js
```

**문법 검사만으로는 부족합니다.** 실제로 겪은 일입니다 — 조절판이 화면 그리기 전에

흩어져 있으면 코드가 조금만 옮겨져도 어떤 검사는 통과하고 어떤 검사는 죽습니다.

## 무엇을 보나

### 두 가지를 따로 잽니다

| | 단위 | 잡는 것 |
|---|---|---|
| **글자 겹침** | 연속 8글자 | 토씨 하나 안 바꾼 복붙 |
| **골격 겹침** | 고유명사를 지운 뒤 연속 5어절 | 주제어만 갈아끼운 템플릿 |

골격 겹침이 이 도구의 핵심입니다. 아래 두 문장은 연속 8글자가 한 번도 안 맞아
글자 겹침으로는 **전혀 안 잡히지만**, 골격으로는 잡힙니다.

> 탄소중립을 주제로 논문을 읽고 실험을 설계해 결과를 도출함
> 유전자가위를 주제로 서적을 읽고 조사를 설계해 자료를 도출함

고유명사는 형태소 분석기 없이 **어절 문서빈도로 근사**합니다.
그 학생만 쓴 어절이 곧 그 학생 고유의 것이라는 원리이고, 숫자·영문·인용부호(「」 등)는 항상 고유명사로 봅니다.

### 공통 활동은 감점하지 않습니다

여러 학생이 함께 쓴 구간이라고 다 문제가 아닙니다. 오히려 **공유 인원에 따라 의미가 정반대**입니다.

| 함께 쓴 인원 | 정체 | 처리 |
|---|---|---|
| 다수 (기본 30% 이상) | 수행평가명·프로그램명·전문용어 | **점선만 긋고 감점하지 않음** |
| 소수 (2~5명) | 돌려쓰기 의심 | **색을 칠하고 유사 인원 표시** |
| 없음 | 그 학생 고유 | 표시 없음 |

연수에서 들으신 "수행평가명이나 공통 프로그램 참여 문장은 감점 요소가 아니다"를 그대로 반영한 것입니다.
**색이 칠해진 구간만 보시면 됩니다.**

공통으로 분류한 표현은 `반복 표현` 탭 맨 아래에 목록으로 나옵니다.
거기에 활동명이 아니라 **학생의 행동이나 판단을 서술한 문장**이 섞여 있다면,
반 전체가 같은 서술을 쓰고 있다는 뜻이라 오히려 가장 시급합니다.

### 생존 분량

전체 글자 중 **어떤 구간에도 걸리지 않은 비율**입니다. 대학이 실제로 읽을 분량에 해당합니다.

명단은 이 값이 낮은 순으로 정렬되니, 위에서부터 손보시면 됩니다.

### 칠한 곳을 누르면 근거가 나옵니다

<b>유사 3명</b> 이라는 숫자만으로는 무엇을 고쳐야 할지 알 수 없습니다.
칠해진 구간이나 옆의 알약을 누르면, **같은 구간을 쓴 학생들의 문장이 그 자리 아래에** 놓입니다.
**같은 반**인 사람이 위로 옵니다. **[이 학생 보기]** 로 바로 넘어갈 수 있습니다.

그대로 겹침은 글자가 같으니 상대 본문에서 그대로 찾으면 됩니다.
**문형 겹침은 글자가 서로 다릅니다.** 그래서 골격(고유명사를 지운 어절열)에서
같은 조각을 찾은 뒤, 그 어절의 자리로 상대 본문 위치를 되짚습니다.

```
골격     "주제로 자료를 모아 · 정리하였고, · 근거로 결론을 이끌어 냄."
2반 3번  "인구 이동을 주제로 자료를 모아 산점도로 정리하였고, 상관계수를 근거로…"
2반 6번  "감염병 확산을 주제로 자료를 모아 꺾은선그래프로 정리하였고, 증가율을 근거로…"
```

바뀐 것이 주제어뿐이라는 게 한눈에 보입니다. `node _test_compare.js` 가
예시 학년의 모든 구간에 대해 상대 자리를 빠짐없이 짚는지 확인합니다.

### 읽기 화면

원문 위에 구간을 겹쳐 그리고 `유사 N명` 을 붙입니다. 연수에서 보신 화면과 같은 방식입니다.

**앞쪽(활동명·도서명)에 붙은 표시는 정상입니다.** 감점 요소가 아니고 고치실 필요도 없습니다.
학생의 행동·판단·변화를 서술한 **뒷부분에 붙은 표시**를 먼저 보세요.

### 고치기 · 나이스 바이트

기록 화면에서 **[고치기]** 를 누르면 그 자리에서 수정할 수 있습니다.
**[저장하고 다시 검사]** 를 누르면 고친 내용으로 곧바로 다시 분석하므로,
**겹침 표시가 실제로 사라졌는지 그 자리에서 확인**할 수 있습니다.

분량은 나이스 글자수 계산기와 같은 방식으로 셉니다.

```
한글 3바이트 · 영문·숫자·공백·문장부호 1바이트 · 줄바꿈 2바이트
```

실제 나이스 파일로 대조해 확인했습니다 — 241자 기록이 583바이트로 동일하게 나옵니다.

상한은 조절판의 **분량 기준**에서 고릅니다.

| 항목 | 상한 |
|---|---|
| 과목별 세특 · 자율 · 동아리 · 진로활동 | 1,500바이트 (한글 500자) |
| 행동특성 및 종합의견 | 900바이트 (한글 300자) |

**2026학년도 기준입니다.** 이해 바뀐 것 — 진로활동이 2,100 → 1,500 으로,
행동특성 및 종합의견이 1,500 → 900 으로 줄었습니다.

> 상한은 학년도 훈령에 따라 달라집니다. 바뀌면 `index.html` 의 `limitSel` 항목과
> 그 아래 안내에 적힌 연도를 함께 고치세요. `node _test_bytes.js` 가
> 선택지와 안내 연도가 실제로 있는지 확인합니다.

92%를 넘으면 노란색, 넘치면 빨간색으로 바뀌고 초과 바이트를 함께 보여줍니다.

고친 기록은 명단에 **수정됨** 배지가 붙고, **[원래대로]** 로 되돌릴 수 있습니다.

### 수정본 내보내기

조절판의 **[수정본 내보내기]** 를 누르면 원본 표의 **모든 열을 그대로 두고
세특 내용만 고친 것으로 바꿔** CSV로 내려받습니다. UTF-8 BOM이라 엑셀·한셀에서
한글이 깨지지 않고, 열어서 나이스에 붙여 넣으시면 됩니다.

**여러 파일을 합쳐 보셨다면 되돌릴 때도 올린 파일 단위로 쪼개서** 내려받습니다.
나이스에는 원래 뽑은 단위 그대로 올려야 하기 때문입니다. 각 파일의 **원래 열 순서를
그대로 두고** 세특 칸만 바꾸며, **고친 곳이 있는 파일만** 내려받습니다.
브라우저가 "여러 파일 내려받기"를 물어보면 허용해 주세요.

고친 내용은 **브라우저 메모리에만** 있습니다. 탭을 닫거나 [바꾸기]로 파일을 교체하면
사라지니, 작업을 마치면 반드시 내보내세요. (닫기 전에 한 번 확인창이 뜹니다.)

### 관계망 (3D)

명단은 학생을 한 줄씩 보여줄 뿐 **여럿이 서로 얽힌 덩어리**를 못 보여줍니다.
40명이 사실상 대여섯 문형으로 수렴하는 상황은 목록으로는 안 보이고 관계망으로만 보입니다.

- **점** = 학생, 크기는 겹치는 학생 수, **흐릴수록 뒤쪽**
- **굵은 실선(빨강)** = 같은 반끼리 겹침
- **가는 점선(회색)** = 다른 반과 겹침

| 조작 | |
|---|---|
| 빈 곳 끌기 | 시점 회전 |
| 점 끌기 | 그 학생을 옮기면 이웃이 따라옴 |
| 점 누르기 | 그 학생의 기록으로 이동 |
| 휠 | 확대·축소 |
| 회전 멈춤 / 시점 초기화 | 오른쪽 위 버튼 |

**천천히 도는 것은 장식이 아닙니다.** 3D 노드 그래프는 가림과 깊이 모호성 때문에
가만히 있으면 2D보다 읽기 어렵습니다. 회전이 만드는 운동 시차가 그 단점을 메웁니다.
멈춰 두고 직접 돌려 보셔도 됩니다. **시스템에서 "동작 줄이기"를 켜 두셨다면 자동 회전은
꺼진 채로 시작합니다.**

**겹침이 없는 학생은 그리지 않습니다.** 대부분이 여기 속하고, 다 그리면 정작 봐야 할
덩어리가 점 무더기에 묻힙니다. 몇 명을 뺐는지는 위에 적어 둡니다.

색만으로 구분하지 않습니다 — 다크 모드에서 적록색약(protan) 기준 붉은 선과 회색 선의
색차가 기준(ΔE 8)에 못 미쳐(6.2), **굵기와 점선을 함께** 씁니다. 색을 전혀 못 가려도
구분됩니다. 누를 자리는 그려진 점보다 넉넉하게(최소 지름 26px) 잡아 두었습니다.

배치는 난수를 쓰지 않아 **같은 데이터면 항상 같은 그림**이 나옵니다.
200명·892개 연결에서 배치 17ms, 한 프레임 0.37ms입니다.

> 관계망은 구조를 보는 화면이지 수치를 읽는 화면이 아닙니다.
> 정확한 값은 **표** 탭에서 확인하세요.

## 설정값

**설정을 바꾸면 결과가 즉시 다시 계산됩니다.** 세부 설정 아래에
"지금 기준이면 25명 중 6명이 확인 대상입니다" 처럼 표시되니, 숫자를 감으로 돌리지 않고
결과를 보면서 맞추시면 됩니다. 보고 있던 학생과 탭은 그대로 유지됩니다.

| 항목 | 기본 | 의미 |
|---|---|---|
| **최소 구간 길이** | 20 | 이보다 짧게 겹친 구간은 버림 |
| **공통 활동 기준** | 12% | 전체의 이 비율 이상이 함께 쓴 구간은 공통 활동으로 보고 감점하지 않음 |
| 겹침 탐지 단위 | 8 | 연속 몇 글자부터 겹침을 찾기 시작할지 |
| 골격 겹침 단위 | 5 | 고유명사를 지운 뒤 연속 몇 어절이 같으면 같은 문형으로 볼지 |
| 표시 최소 인원 | 1 | 몇 명 이상 겹칠 때 표시할지 |
| 고유명사 판정 | 1 | 이 인원 이하만 쓴 어절을 고유명사로 보고 골격에서 지움 |

**표시가 너무 빡빡하면 이 둘을 조절하세요.**

- 전문용어나 활동명 하나로 걸린다 → **최소 구간 길이**를 올립니다 (16 → 22 등)
- 반 전체가 쓰는 표현이 자꾸 걸린다 → **공통 활동 기준**을 내립니다 (30% → 20% 등)

반대로 너무 헐거우면 각각 내리고 올리면 됩니다.
